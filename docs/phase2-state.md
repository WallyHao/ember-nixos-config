## Keyring

GNOME Keyring is the only Secret Service provider. Greetd's PAM stack is
custom, so `session.nix` adds `pam_gnome_keyring` to auth, password, and
session rules. `security.pam.services.login.enableGnomeKeyring` and
`security.pam.services.passwd.enableGnomeKeyring` cover local login/password
changes. The persisted `~/.local/share/keyrings` must be unlocked by the same
password at login; no empty-password keyring and no key material is written to
the Nix store, repository, or logs.

`vm-desktop` checks the real password login and the keyring-related services.
If the locked PAM cannot synchronize a changed password with the keyring, the
manual recovery is: log in with the new account password, unlock the existing
Login keyring with its previous password, then change the keyring password to
the current account password. Do not delete the keyring or empty its password.
That limitation must be reported rather than hidden.

## Noctalia

Noctalia's durable encrypted history lives under
`~/.local/state/noctalia`. Its `settings.toml` is a GUI override layer and wins
over the managed `~/.config/noctalia/config.toml`; that is expected. The
managed palette is `~/.config/noctalia/palettes/emberlight.json`. The storage key
is requested from the Secret Service; no key is placed in a config file.

Phase 3 adds two app-recognised markers and one backup inside this directory:
`.setup-complete` (stops Noctalia serving its bundled first-run wallpaper when
the wizard is disabled), `.hearth-phase3-appearance` (one-time migration
version), and `settings.toml.pre-phase3` (backup taken before appearance-owned
overrides are removed once). They are runtime state, not managed config.

## Native profile

`~/.local/state/nix/profiles/profile` is a normal Nix profile, installed by
`wallyhao` from `software#base`. Home Manager only prepends its `bin` and
`share` to the session. No Home Manager activation or login script runs
`nix profile install`. The profile is independent of the HM generation and
survives HM activation; phase 1 already verified the profile directory and
its private-store GC behavior.
