# Operations

## First login (future installed system)

The default entry is greetd/tuigreet; log in as `wallyhao` with the initial
four-character password defined in the phase plan. Change it at the first
opportunity:

```sh
passwd
```

After login, the session starts `niri-session`, Noctalia, and the user services.
tty2 is kept as a password-protected rescue VT. There is no autologin.

Install the base CLI profile as `wallyhao`; it is independent of the system and
Home Manager generations:

```sh
cd /path/to/hearth-nixos-config
nix profile install --no-update-lock-file \
  --profile "$HOME/.local/state/nix/profiles/profile" \
  'path:./software#base'
```

Use native profile commands:

```sh
nix profile list
nix profile history --profile "$HOME/.local/state/nix/profiles/profile"
nix profile rollback --profile "$HOME/.local/state/nix/profiles/profile"
```

The current configuration preserves a normal `passwd` change across reboots
and userborn restarts. This relies on the local PAM compatibility patch; keep
the account VM checks when updating inputs. See
[the password resolution](phase1-blocker-password.md).

`sudo` requires the account password. Root password login is locked; do not
set the same bootstrap password for root.

## Boot menu

systemd-boot is configured with `timeout = 0`, so the newest generation boots
without a countdown. The menu is not removed:

- Hold **Space** during boot to enter the menu.
- To request the menu for the next boot only:

```sh
bootctl set-timeout-oneshot 5
```

- Or schedule a one-shot menu reboot (do not run this in phase 1):

```sh
systemctl reboot --boot-loader-menu=5
```

`configurationLimit = 5` limits entries to the five most recent retained
generations. A new installation with fewer generations shows the actual
entries. This limit is not the garbage-collection retention count.

## Recovery

Select an older generation in the printed systemd-boot menu. Historical store
paths remain until garbage collection. The weekly Hearth GC service trims the
system profile to the newest five generations and then collects unreachable
store paths; booted/current roots are preserved.

To force a one-off boot without activating the host:

```sh
/run/current-system/bin/switch-to-configuration boot
```

is an activation-time command and is **not** part of phase-1 execution.

## Network

NetworkManager owns connections. DNS uses systemd-resolved. There is no
automatic proxy, subscription download, or TUN integration yet. A missing
network must not block local login.

## Graphical session

- Greeter: greetd + tuigreet on tty1; no automatic session.
- Niri: managed KDL at `~/.config/niri/config.kdl`.
- Shell: Noctalia v5, one top bar, native Polkit agent, offline mode.
- Terminal: Foot (no foot server), using the managed Hearth palette.
- Audio: PipeWire/WirePlumber with rtkit; PulseAudio daemon is disabled.
- Keyring: GNOME Keyring is the only Secret Service; greetd PAM unlocks the
  Login keyring with the login password.
- Portals: GTK file chooser and GNOME sharing/Secret backend; Nautilus is not
  installed by the Niri module.

If the session fails, switch to tty2 and use the normal password login. Inspect
`systemctl status greetd`, `systemctl --user status niri noctalia`, and the
journal. Do not remove the keyring or add a second Polkit agent to work around
a failure.

Noctalia's GUI settings are stored in `~/.local/state/noctalia/settings.toml`
and can override the managed `~/.config/noctalia/config.toml`; this is
expected. Managed files are regenerated by the next system/Home Manager
activation.

## Maintenance commands

```sh
scripts/hearth info
scripts/hearth check
scripts/hearth build
just software-build
```

The script refuses `switch`, `test`, `boot`, `install`, and `activate`.
`system.autoUpgrade` and automatic rebuild are disabled. The lock is not updated
by normal checks.

## Logs and cleanup

journald is persistent, capped at 128 MiB with 14-day retention. fstrim runs
weekly, not during boot. `nix-store --optimise` remains a manual maintenance
operation; it is not run on every store write.

## Not supported yet

- Installation to the internal disk.
- Disk swap or hibernation.
- Secure Boot or encrypted root for the new system.
- Input method, QQ/WeChat, browser, or a full software manager.
- Secrets deployment framework and automatic proxy.
- Real hardware performance, suspend, display, and input-device validation.
